1. 面积 (Cell Area)

面积影响

fanout=4 比 unset 多消耗 8.3% 面积（5,934 µm²），主要来自大量 buffer 树插入

2. Buffer 数量 (Buf/Inv Cell Count)

Buffer 成本

fanout=4 插入了 9,683 个 buffer，是 unset 的 5.6 倍，且这些 buffer 几乎全是为解决高扇出而加的

3. 关键路径延迟 (Critical Path Delay)

时序分析

fanout=64 意外出现最长路径（1.29ns），且 Levels of Logic=24（最高），出现 Max Cap Violations。DC 在宽松约束下优化方向偏离

4. 功耗 (Total Power = Dynamic + Leakage)

功耗分析

总功耗差异仅 0.17mW（1.9%），主要来自 buffer 的动态功耗增量，但本设计中泄漏功耗占比更高（~15%），所以整体差异不显著

关键发现

🎯

最优值：fanout=16

buffer 数量、面积、时序三者达到最佳平衡。是本项目和大多数 ASIC 设计的推荐默认值。

⚡

时序全部 Meet

6 组实验在 500MHz 下全部 WNS=0.00，说明本设计不受 fanout 限制，瓶颈在逻辑深度而非布线。

⚠️

fanout=64 异常

LoL=24（最高）且 CP=1.29ns（最长），出现 4 个 Max Cap Violations。过大 fanout 反而导致 DC 优化失控。
